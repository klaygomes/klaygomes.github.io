# specification.website checklist

Source: https://specification.website/checklist/ and https://specification.website/spec/well-known/

Hosting: GitHub Pages behind Cloudflare. Response headers cannot be set from this repo; they need Cloudflare rules (see "Outside the repo").

## Lead (sequential, shared files)

- [ ] L1 `_config.yml`: `include: [.well-known]` so Jekyll publishes `/.well-known/`. Accept: `_site/.well-known/` exists after build.
- [ ] L2 Restore a working Jekyll build (Docker daemon returns 500, host Ruby zlib broken).
- [ ] L3 Review merged diff against `master`, verify each teammate's evidence.

## Teammate A: discovery and machine-readable files (owns new root files, `feed.xml`, `.well-known/`)

- [x] A1 `robots.txt` (RFC 9309) with `Sitemap:` line and explicit AI-crawler groups. Accept: `_site/robots.txt` served as text, lists sitemap URL.
- [x] A2 `sitemap.xml` generated by Liquid (no new gem), skipping pages with `sitemap: false`. Accept: valid XML, every post URL absolute, no 404/feed.
- [x] A3 `/.well-known/security.txt` (RFC 9116): `Contact`, `Expires` < 1 year, `Canonical`, `Preferred-Languages`. Accept: file in `_site/.well-known/`.
- [x] A4 `llms.txt` listing site summary and posts with absolute URLs. Accept: markdown, H1 first line.
- [x] A5 `feed.xml` hygiene: author from `site.author` (currently empty `site.owner`), stable ids, well-formed. Accept: `xmllint --noout` passes, `<name>` non-empty.

## Teammate B: head metadata and structured data (owns `_includes/head.html`, `_layouts/post.html`, `_layouts/page-index.html`, `_posts/*` front matter)

- [x] B1 `<meta name="color-scheme">` and `<meta name="referrer" content="strict-origin-when-cross-origin">`.
- [x] B2 Meta robots: `noindex` on `404.html` (via front matter flag rendered in head).
- [x] B3 JSON-LD: `WebSite` + `Person` on home, `BlogPosting` + `BreadcrumbList` on posts. Accept: parses as JSON, required fields present.
- [x] B4 `<link rel="sitemap">` discovery in head; posts in Portuguese carry `lang: pt-BR` (verify each post body language).
- [x] B5 Mixed content safety net: `<meta http-equiv="Content-Security-Policy" content="upgrade-insecure-requests">`.

## Teammate C: privacy, consent, resilience (owns `_includes/disqus_comments.html`, `_includes/footer.html`, new `privacy.md`, `site.webmanifest`, `browserconfig.xml`)

- [x] C1 Disqus loads only after an explicit click (cookie consent, Required). Accept: no request to `disqus.com` on page load.
- [x] C2 `privacy.md` page describing what the site actually does (GitHub Pages, Cloudflare, Google Fonts, Disqus on opt-in, localStorage keys). Linked from footer.
- [x] C3 `site.webmanifest`: `id`, `start_url`, `scope`, brand `theme_color`, `lang`, maskable icon. Accept: valid JSON.

## Outside the repo (needs owner, Cloudflare dashboard)

- [ ] HSTS `Strict-Transport-Security: max-age=31536000; includeSubDomains` (Required)
- [ ] `X-Content-Type-Options: nosniff` (Required)
- [ ] `Content-Security-Policy: frame-ancestors 'none'` + `X-Frame-Options: DENY` (Required, cannot be set by meta tag)
- [ ] `Referrer-Policy`, `Permissions-Policy` headers (Recommended)
- [ ] Cache-Control for fingerprinted assets (Required; GitHub Pages fixes `max-age=600`)
- [ ] DNS CAA record (Recommended)

## Already compliant (checked live / in source)

- [x] doctype, `lang`, charset, viewport, title, description, canonical, Open Graph, feed `rel=alternate`
- [x] HTTPS, HTTP→HTTPS 301, apex→www 301, HTTP/2 + HTTP/3, compression (Accept-Encoding vary)
- [x] Custom 404 returns real 404 status
- [x] Skip link, `<main>` landmark, reduced-motion handling in footer/CSS
- [x] Inline `lang: pt-BR` on two Portuguese posts

## Not applicable

- change-password, webauthn, openid-configuration, oauth-*, webfinger, apple-app-site-association, assetlinks, nodeinfo: no accounts, apps, or federation
- api-catalog: no APIs; GitHub Pages cannot serve `application/linkset+json`
- Form labels / form errors / authentication: no forms

## Found during work

- A5: the old feed piped `post.modified` through a nonexistent `to_xmlschema` filter and appended a fixed time, so `<updated>` was invalid for the post with `modified: 20-06-2021`. Now `date_to_xmlschema` with a fallback to `post.date`.
- A2/A5: `_posts/2021-06-20-dotfiles-configuration.md` uses `modified: 20-06-2021` (DD-MM-YYYY string); it parses correctly today, but ISO `2021-06-20` would be safer (Teammate B owns `_posts/*`).
- Sitemap/feed timestamps take the build machine's timezone (no `timezone:` in `_config.yml`); CI builds in UTC, so offsets differ between local and deployed builds.

- B: `about` and `curso-stm32` use `layout: post` without being posts; JSON-LD is gated on `page.collection == "posts"` so they get none.
- B: post body language checked for all 16 posts; only the 2009 calls and 2016 async posts are Portuguese (both already `lang: pt-BR`).
- B: no dark-mode styles exist, so `color-scheme` is `light`; switch to `light dark` if dark tokens are added.
- C: `_layouts/post.html` includes Disqus unconditionally, ignoring `comments: false` (about.md sets it), so `/about/` and `/curso-stm32/` show the comments prompt. Gate the include on `page.comments != false`.
- C: `/curso-stm32/` embeds 6 `youtube.com/embed` iframes that load on view and set YouTube cookies without consent; switch to `youtube-nocookie.com` or click-to-load. `/about/` hotlinks a stackexchange.com flair image. Both are disclosed on `/privacy/`.
- C: `android-chrome-512x512.png` fills the canvas edge to edge, so icons are `"purpose": "any"`; a padded maskable icon (content inside the 80% safe zone, brand background) is still needed.
- C: `.btn-primary` had no visible keyboard focus (its `box-shadow` overrode the base `:focus-visible` ring); fixed site-wide in `main.postcss.css`.
- C: Disqus `disqus_config` sets only `page.url` (canonical https URL); no `page.identifier`, since existing threads were created without one and a new identifier would orphan them. Threads created under an old domain/http URL may need Disqus's URL mapper.
